## Cause racine prouvée

Le défaut se trouvait dans l'orchestrateur local de la tentative précédente :
`work/cold_execution.py`, appel subprocess à la ligne 115 de cette version.
Le fichier cible était
`C:\Users\waelo\Documents\Codex\2026-10-23\mission-stockpilot-ai-v13-9-3\work\windows-preflight.ps1`.
L'interpréteur refusait de charger le fichier avant sa première instruction ;
aucune ligne interne du ps1 n'avait encore été exécutée. Cet appel n'était pas
présent dans le runbook original de la PR #58.

Commande reproduite, avec un tableau d'arguments Python depuis WSL Ubuntu :

```text
/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe
  -NoProfile -NonInteractive -File
  C:\Users\waelo\Documents\Codex\2026-10-23\mission-stockpilot-ai-v13-9-3\work\windows-preflight.ps1
```

Code de sortie **1**, stdout vide. Texte de stderr (espaces de fin de ligne omis),
décodé avec l'encodage console OEM cp850 ; les octets exacts hexadécimaux sont
conservés dans le diagnostic local :

```text
Impossible de charger le fichier
C:\Users\waelo\Documents\Codex\2026-10-23\mission-stockpilot-ai-v13-9-3\work\windows-preflight.ps1, car l'exécution de
scripts est désactivée sur ce système. Pour plus d'informations, consultez about_Execution_Policies à l'adresse
https://go.microsoft.com/fwlink/?LinkID=135170.
    + CategoryInfo          : Erreur de sécurité : (:) [], ParentContainsErrorRecordException
    + FullyQualifiedErrorId : UnauthorizedAccess
```

La lecture de `Get-ExecutionPolicy` donnait `Restricted`. C'est donc un refus
réel de l'interpréteur pour `-File`, et non une erreur Docker, un chemin absent,
un problème de quoting WSL ou un processus concurrent détecté. Le diagnostic
utilisait le chemin Windows absolu dans argv, sans shell et sans PSMODULEPATH
hérité. Le résultat de refus de la tentative n'avait pas conservé stderr et
affichait le nom du contrôle Linux précédent : cette mauvaise localisation est
explicitement corrigée. Le nouveau helper conserve un motif de refus canonique.

## Correctif opérationnel

- `scripts/b2b_windows_preflight.js` utilise cscript.exe / WMI, StdRegProv et FSO,
  disponibles sur ce poste. Les sources de preuve sont équivalentes à celles du
  ps1 : Win32_Process, Win32_LogicalDisk, registre Lxss, attributs des deux VHDX
  et de chacun de leurs parents. Aucun PowerShell ni paquet Windows tiers requis.
- `scripts/b2b_cold_preflight.py` est un point d'entrée exclusivement en lecture
  seule. Il appelle le helper Windows par argv avec chemin `wslpath -w` et nonce,
  conserve les contrôles load/attest, flock, volumes exclusifs et processus/cgroups,
  puis compare les métadonnées et empreintes privées avant/après. Il n'a aucun
  chemin de code de sauvegarde ou de cycle de vie Docker.
- Le runbook fournit la commande de préflight seule, le contrôle Windows/Linux
  sous verrou avant création d'un futur bundle, et réutilise le contrôle cgroups
  strict avant les futures copies. Les sections de sauvegarde/restauration ont
  seulement été vérifiées en syntaxe ; elles n'ont pas été exécutées.
- Le lanceur local de la tentative précédente appelle désormais le même helper
  natif à la place de PowerShell. Son exécution complète n'a pas été lancée.

Linux /proc ne permet pas de remplacer l'observation des processus Windows et
de leurs commandlines. Docker seul ne prouve pas non plus l'espace physique C:
ni les reparse points des VHDX. La commande PowerShell particulière n'est donc
pas indispensable ; **les preuves Windows correspondantes le restent**.

Toute erreur WSH/WMI/registre, sortie mal formée, cmdline de candidat inaccessible,
attribut ou espace inconnu, reparse point, volume partagé, processus source,
témoin absent ou distribution WSL active non observée provoque BLOCKED.
Le helper Windows prouve sa propre visibilité par nonce. Un candidat disparu
pendant l'énumération est ignoré uniquement si une seconde requête constate son
absence ; PID réutilisé ou identité non confirmée provoque un refus.

Aucune stratégie d'exécution n'a été modifiée ; aucun Bypass et aucune protection
Windows désactivée. Si Windows Script Host est interdit sur un autre poste,
l'échec reste BLOCKED, sans contournement automatique.
