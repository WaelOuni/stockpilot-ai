# V13.9.3 — conservation à froid avant récupération sur copie

**COMMANDES PROPOSÉES, NON EXÉCUTÉES.** Lire le
[rapport de reprise Docker](../reports/v13.9.3-docker-readonly-resumption.md).
La source est arrêtée avec sortie255. Ce document ne propose aucun start/stop
source, aucun init, aucune réparation ni migration. Une autorisation de copie
ne vaut pas autorisation de restauration, de démarrage de clone ou d'upgrade.

La copie conserve l'état physique, y compris WAL, journaux, utilisateurs/rôles,
catalogues et registres. Sa cohérence métier et sa récupérabilité ne sont pas
déjà prouvées. Nom du type de point : **cold-physical-unvalidated**.
Ne pas lui appliquer pg_restore ou mongorestore, qui attendent d'autres formats.

Utiliser le checkout du correctif vérifié et son venv propre. Le résultat attendu
est `READY TO RETRY COLD BACKUP`, pas `COLD BACKUP VERIFIED`. Les preuves privées
avant/après sont conservées dans SP_AUDIT ; SP_NEXT reste absent. Ce résultat ne
relance aucune sauvegarde. Toute nouvelle fenêtre exige des mesures fraîches.

Le refus du 23 octobre venait du script local d'orchestration de la tentative,
pas d'une commande PowerShell présente dans la version initiale de ce runbook :
`powershell.exe -NoProfile -NonInteractive -File .../windows-preflight.ps1`.
Windows PowerShell `Restricted` refuse ce fichier avant son exécution, avec
`UnauthorizedAccess`. Ne pas changer la stratégie et ne pas utiliser Bypass.

Le remplacement est `scripts/b2b_windows_preflight.js`, appelé par cscript.exe
depuis Python avec un tableau d'arguments, sans shell, un chemin Windows obtenu
par `wslpath -w`, un nonce et le seuil de capacité. Il utilise les mêmes preuves
Windows : WMI Win32_Process/Win32_LogicalDisk, registre Lxss, attributs FSO des
VHDX et de tous leurs parents. Aucun paquet tiers Windows ni PowerShell requis.
Le témoin Windows est le processus cscript portant le nonce. Un candidat disparu
n'est ignoré qu'après une seconde requête prouvant son absence ; PID réutilisé,
cmdline inaccessible, erreur WMI/WSH/registre, attribut inconnu ou reparse point
entraînent BLOCKED. Aucun contenu de cmdline ou de secret n'est affiché.

Les contrôles Linux/Docker restent obligatoires : load/attest sans worker,
six IDs/images et quatre identités de volumes, source exited/PID0/sortie255,
volumes exclusifs, empreintes privées, flock, scan /proc Ubuntu et cgroups de
Docker Desktop avec témoins actifs positifs. Seules Ubuntu et docker-desktop
peuvent être déjà actives ; distribution supplémentaire non observée = BLOCKED.
Le socket doit être exactement unix:///var/run/docker.sock, y compris DOCKER_HOST.
C: doit conserver au moins 36 Gio avant copie (flux borné de 6 Gio + réserve de
30 Gio). Ubuntu/Docker doivent aussi avoir cette capacité ; leurs espaces virtuels
ne sont jamais additionnés à C:. Les deux fichiers VHDX attendus doivent exister
sur C: aux chemins vérifiés. Un déplacement de stockage exige un nouveau diagnostic.

Les métadonnées de tous les conteneurs, volumes, réseaux et images sont comparées
avant/après. Seul l'ordre sans signification des listes Mounts/tags/digests est
normalisé ; les valeurs, labels et publications actives restent comparés. Les
fichiers privés source sont relus et comparés par hash/mode/UID/GID/taille/mtime.
Ces observations et le verrou coopératif ne peuvent exclure un client API externe
arbitraire qui ignore ce verrou. Ce préflight n'est pas une preuve de récupération.

### Lancement Windows/WSL explicite

Le lanceur `scripts/wsl_launcher.py` fixe le cwd Windows à System32 et utilise
des tableaux argv sans shell : `wsl.exe --distribution Ubuntu --cd /home/waelko
--exec ...` pour Ubuntu, et `--distribution docker-desktop --cd / --exec ...`
pour les inspections du moteur déjà actif. La liste des distributions est
interrogée sans exécution Linux, depuis le même cwd hôte explicite.

Ne pas hériter d'un cwd UNC Ubuntu pour appeler une autre distribution : cela
produisait `wsl: Failed to translate ...` dans le contrôle supplémentaire de la
campagne précédente, malgré un code0. Le nouveau lanceur ne filtre aucun message :
tout stderr non vide, code non nul, cwd indisponible, timeout ou WSL absent reste
un refus. cscript/WMI reçoit aussi un cwd Windows fixe ; ses refus sont inchangés.
Le préflight Windows/WSL précède désormais toute inspection Docker dans le runner.

Les outils de vérification supplémentaires doivent appeler `wsl_command` et
`running_distributions` du même module de préflight, sans invocation WSL parallèle.
Une campagne refusée ne doit pas être relancée dans la même fenêtre ; conserver
ses preuves et toute archive partielle.

## 2. Vérifier les images OCI, sans confondre configuration et index

Les six IDs observés sont des digests d'index OCI. Il est incorrect d'exiger
qu'ils soient égaux au digest Config de manifest.json. L'index racine, son
manifest linux/amd64, la configuration et les couches ont des identités distinctes.
[OCI image layout](https://github.com/opencontainers/image-spec/blob/main/image-layout.md),
[docker save](https://docs.docker.com/reference/cli/docker/image/save/).

Vérification proposée, **sans import**, à exécuter uniquement après export.
Elle refuse un export qui ne conserve pas les six index d'origine comme racines.
Une différence de format provoque NO-GO, jamais une suppression de garde-fou.

```sh
.venv/bin/python - <<'PY'
import hashlib,json,os,pathlib,tarfile
p=pathlib.Path(os.environ['SP_JOB'])
def verify_native(t,expected):
    names=[x.name for x in t.getmembers() if x.isfile()]
    assert len(names)==len(set(names))
    assert json.load(t.extractfile('oci-layout'))['imageLayoutVersion']=='1.0.0'
    root=json.load(t.extractfile('index.json'))
    by_digest={x['digest']:x for x in root['manifests']}
    assert set(expected)==set(by_digest)
    def blob(desc,parse=False):
        digest=desc['digest'];algorithm,value=digest.split(':',1)
        assert algorithm=='sha256' and len(value)==64 and all(x in '0123456789abcdef' for x in value)
        member=t.getmember('blobs/sha256/'+value)
        assert member.isfile() and member.size==desc['size']
        h=hashlib.sha256();parts=[]
        if parse:assert member.size<8*1024*1024
        with t.extractfile(member) as f:
            while block:=f.read(1024*1024):
                h.update(block)
                if parse:parts.append(block)
        assert h.hexdigest()==value
        return json.loads(b''.join(parts)) if parse else None
    for iid in expected:
        index=blob(by_digest[iid],True)
        native=[x for x in index['manifests'] if x.get('platform',{}).get('os')=='linux'
                and x.get('platform',{}).get('architecture')=='amd64']
        assert len(native)==1
        manifest=blob(native[0],True)
        config=blob(manifest['config'],True)
        assert config['os']=='linux' and config['architecture']=='amd64'
        for layer in manifest['layers']:blob(layer)
with tarfile.open(p/'rollback-images.tar') as t:
    expected=json.loads((p/'source-image-identities.json').read_text())
    verify_native(t,expected)
print('Index d’origine et contenu linux/amd64 vérifiés. Aucun load ni test runtime effectué.')
PY
```

Ce contrôle ne qualifie pas les variantes non natives et ne remplace pas un
load isolé. Les racines exactes doivent être retrouvées après ce futur load.
Ne pas importer dans le moteur partagé pour contourner une absence de preuve.
En particulier, ne pas déduire le futur ID d'image du champ Config de l'ancien
manifest Docker. Une importation/tag modifié pourrait toucher les autres démos.

```sh
    (p/'physical-restore-ids.json').write_text(json.dumps({'prefix':prefix,'containers':created,'volumes':volumes},indent=2))
print('Trois clones préparés et arrêtés. Vérification des fichiers avant tout démarrage.')
PYCODE
```

Si le format tar ne fournit pas une racine `.` avec les UID/GID attendus, arrêter
et examiner l'inventaire ; ne pas choisir un UID arbitraire. Comparer les fichiers
extraits, leurs tailles, hashes, modes et UID/GID à chaque archive, par lectures
sur les seuls clones arrêtés. Aucun répertoire source n'est une destination.
La restauration physique et sa récupération n'ont pas été démontrées ; ce bloc
est une proposition concrète à éprouver, pas un test déjà réussi.

Le démarrage des clones est encore une étape explicite de cette autorisation :
binaires postgres/mongod directement, UID/GID de l'archive, mêmes versions majeures,
réseaux none et sans health check initialisateur. Mongo : rs0 et keyFile restaurés,
localhost27017, TTL désactivé **sur la copie uniquement**. PostgreSQL : PGDATA
restauré, port interne approprié, sockets tmpfs privés. Aucun init, repair,
pg_resetwal, seed, rs.initiate ou migration apply.

Laisser les moteurs effectuer leur récupération normale sur **ces nouvelles
copies seulement**. Échec ou WAL/journal manquant = NO-GO, conservation de la
copie et des logs privés filtrés, pas de récupération forcée. Puis contrôler
Mongo3/PG2, marqueurs, FCV/extensions, rôles/ACL, données/checkpoints, réservations
et journaux appariés. Une topologie applicative isolée distincte sera nécessaire
pour Keycloak/BFF et l'isolation A/B ; ce test de fichiers ne la remplace pas.

Le replica set Mongo conserve ses hôtes d'origine dans local.system.replset.
Le clone en réseau none peut donc récupérer ses fichiers sans pouvoir élire un
primary. Ce n'est pas une preuve de cohérence ni une recette applicative ; ne pas
modifier sa configuration pour contourner ce constat. Les contrôles nécessitant
une élection exigent une topologie isolée explicitement approuvée, dont les noms
se résolvent exclusivement vers les nouvelles ressources, jamais vers la source.

## 4. Arrêts de procédure

NO-GO si source réactivée, PID/cgroup source présent, volume partagé/remplacé,
empreinte privée différente, espace insuffisant, quota dépassé, tar illisible,
lien non couvert ou index OCI perdu. Ne pas démarrer la source pour faciliter
un dump ; ne pas utiliser la sauvegarde logique historique dans cet état.
Un checksum conforme prouve le transport, pas l'intégrité logique ni un RPO métier.
