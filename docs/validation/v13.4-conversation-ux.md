## Causes et correction

`useAssistant.ts` conserve déjà une réponse distincte dans chaque message. Les
réponses anciennes ne sont pas remplacées par `state.result`. La disparition venait
uniquement de `:show-advice="message.id === state.messages.at(-1)?.id"` dans
`AssistantConversation.vue`, qui masquait les cartes dès l'ajout du message suivant.
Cette condition est supprimée ; `useAssistant.ts` et l'état LangGraph restent
inchangés. Aucun stockage navigateur persistant n'est ajouté.

La condition d'activation ORDER reste indépendante de l'affichage Advice : seul le
dernier message, hors chargement/erreur/décision déjà tentée et avec un client
connecté, peut émettre une décision. Le gestionnaire vérifie désormais aussi
l'identifiant du message avant d'appeler `decide`. Les contrôles existants dans le
composable et le backend restent applicables. Une fiche historique n'a aucune
action de commande ; son lien ouvre seulement la fiche catalogue actuelle.

Le texte Advice provenait d'un résumé technique fixe et de phrases qui répétaient
les champs de chaque carte. Un helper de présentation déterministe construit les
résumés depuis les produits revérifiés et les critères : cardinalité réelle,
catégorie lisible, budget strict/inclusif, disponibilité, référence et alternatives.
La recherche, l'identité, les filtres, le tri et la relecture MongoDB sont inchangés.
L'appel LLM existant reste borné à un par réponse et ne peut qu'ordonner trois clés
fermées ; aucun texte libre du modèle n'est affiché. Le fallback conserve ses
produits vérifiés et son indication d'indisponibilité du modèle.

Les cartes présentent nom, disponibilité, prix, stock, catégorie et SKU ; les
métadonnées de comparaison et les avertissements hors critères restent visibles.
L'explication détaillée, y compris celle des anciennes réponses, reste accessible
via le contrôle natif « Pourquoi ce produit ? ». Les confirmations historiques
restent visibles et désactivées après question, décision, erreur ou changement de
contexte. Aucun bouton de commande décoratif n'a été ajouté.

## Instantanés et convention numérique

Le domaine `Product`, les DTO et le contrat API ne garantissent aucune devise.
`ProductInfo.vue` affichait déjà des nombres avec `Intl.NumberFormat('fr-FR')`, sans
symbole. Les pages d'administration utilisent aussi des nombres français ; cela
ne constitue pas une convention monétaire EUR. **Aucun symbole €, code EUR ou
nouvelle devise n'est ajouté.**

La conversation indique une fois que la devise n'est pas renseignée. Chaque groupe
Advice porte une note d'instantané : prix et stock ne sont pas actualisés. Les
prix affichés gardent leur précision, avec au moins deux décimales ; les valeurs
qui nécessiteraient plus de vingt décimales passent en notation scientifique
pour éviter de présenter un prix positif comme zéro. Les écarts de comparaison
sont formatés séparément pour éliminer le bruit de soustraction binaire, sans
changer les données API. Les contraintes numériques en prose ne supposent pas de
devise. Les spécifications techniques manquantes restent signalées en comparaison,
et une référence hors budget n'est jamais décrite comme une correspondance valide.

Le scroll suit les nouvelles réponses lorsque le lecteur se trouve à moins de
64 pixels du bas. Lorsqu'il relit un ancien message, sa position reste conservée ;
« Voir la dernière réponse » permet de rejoindre le nouveau contenu. Le défilement
est immédiat, sans animation imposée. Le journal est nommé et accessible au clavier.
Les cartes se replient selon leur largeur ; noms et SKU longs peuvent revenir à
la ligne, sans défilement horizontal sur le viewport mobile testé.

## Limites et protection des installations

L'historique visuel reste en mémoire de la session frontend ; le rafraîchissement
l'efface selon le comportement existant. Il n'est pas un historique serveur et
n'actualise pas les faits des anciennes cartes. Le lien catalogue permet une
nouvelle lecture. Aucun contrat API, schéma, modèle LLM, workflow, repository,
JWT, session, protection HTTP/SaaS ni logique de transaction ORDER n'est modifié.

Les avertissements préexistants de tests sur une clé JWT factice courte et sur la
future sérialisation stricte des enums dans les fixtures sont hors périmètre.
Aucune validation Ollama réel, migration ou nouvelle infrastructure n'est requise
pour ces textes déterministes. Une validation manuelle ultérieure sur une version
candidate actualisée restera une opération distincte.

Les DEMO v017 et V13.3 sont laissées intactes : aucune requête fonctionnelle,
écriture, lecture de secrets, commande de cycle de vie ou modification de fichier
ne leur a été adressée. Seules les métadonnées de leurs conteneurs ont été relevées
pour comparer identifiants, images, démarrages et montages avant/après.
