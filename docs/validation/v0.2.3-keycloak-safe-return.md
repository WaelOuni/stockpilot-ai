# v0.2.3 — retour sûr depuis Keycloak

Branche indépendante `codex/b2b-keycloak-safe-return`, base `main`
`7d7318961588538c7a738ea3e7b8caa105a2501f`. Portée : connexion BFF,
interface de choix d’organisation et thème de connexion. Aucun changement ORDER,
modèle, permission, schéma de données, version de dépendance ou environnement déployé.

## Cause et correction

Le dépôt stable ne fournissait pas de thème applicatif ; la page native n’exposait
pas d’action de retour à StockPilot. Les erreurs fournisseur valides aboutissaient
au refus JSON du callback. Le choix d’organisation reste une intention attachée
à la transaction serveur, jamais une preuve d’appartenance.

Le thème `docker/keycloak/themes/stockpilot` hérite de `keycloak.v2` en **26.8.1**.
Il surcharge seulement les messages FR/EN et le point d’extension `footer.ftl` :
formulaire POST sur `url.loginAction`, bouton natif `cancel=true`, uniquement sur
les pages `login` et `login-password` (réauthentification native). Il conserve les champs et protections du formulaire natif, sans
JavaScript applicatif, URL d’environnement ni remplacement du template principal.
Le titre stable est « StockPilot AI ». L’apostrophe française est échappée pour
MessageFormat.

Ce choix repose sur le [gestionnaire natif UsernamePasswordForm 26.8.1](https://github.com/keycloak/keycloak/blob/26.8.1/services/src/main/java/org/keycloak/authentication/authenticators/browser/UsernamePasswordForm.java),
son [héritage par PasswordForm](https://github.com/keycloak/keycloak/blob/26.8.1/services/src/main/java/org/keycloak/authentication/authenticators/browser/PasswordForm.java),
le [point d’extension du template 26.8.1](https://github.com/keycloak/keycloak/blob/26.8.1/themes/src/main/resources/theme/keycloak.v2/login/template.ftl)
et la [documentation officielle des thèmes](https://www.keycloak.org/ui-customization/themes).

En mode métier, le callback d’erreur vérifie toujours les paramètres autorisés,
l’unicité des paramètres, le state, le cookie navigateur, la configuration,
l’expiration et l’issuer lorsqu’il est fourni. La consommation atomique existante
est partagée entre annulation et échange de code : un seul gagnant. Une annulation
ne fait aucun échange de tokens, aucune sélection de membership, aucune création
ou rotation de session. Une éventuelle session antérieure valide n’est pas révoquée
par cette action ; la déconnexion conserve sa route protégée Origin/CSRF.

Le BFF efface le cookie de transaction puis répond 303 vers la seule destination
`/b2b-app/?login=cancelled` (`failed` pour une autre erreur fournisseur).
Aucune description fournisseur ni URL libre n’est réutilisée. Vue efface cette
indication de l’URL, abandonne la destination de reprise en attente et, pour une
session absente, affiche un message borné avec code d’entreprise vide et focus.
Le mode historique `b2b_auth_test` garde son contrat 401.

La prochaine connexion recrée state, nonce et verifier PKCE ; elle conserve
`prompt=login`, S256, les cookies Secure/HttpOnly/SameSite et la vérification
serveur de l’appartenance. Les tokens OIDC restent côté serveur. Le chemin de
succès, le logout, les expirations et les conversations ne changent pas.

## Build et activation future

Build reproductible depuis le checkout, sans monter un thème privé :

```sh
docker build -f docker/keycloak/Dockerfile -t stockpilot-keycloak:local docker/keycloak
```

Le Dockerfile reprend exactement la version Keycloak existante et embarque le
thème. `--login-return` construit une image locale unique et active le thème
uniquement dans le realm jetable généré par le harnais. Le JSON de realm commun
reste compatible avec les autres campagnes utilisant l’image Keycloak officielle.

Le workflow release actuel ne publie pas cette nouvelle image Keycloak. Lors d’un
futur déploiement explicitement autorisé, il faudra construire/publier cette image
avec le commit revu, vérifier sa provenance et son digest, puis remplacer la
référence Keycloak par ce digest dans la composition existante. Sauvegarder la
configuration du realm et sélectionner `loginTheme=stockpilot`, `displayName=StockPilot AI`
(et le même titre HTML, s’il est renseigné). Pour le sélecteur FR/EN, activer
l’internationalisation, les locales `fr,en` et la locale par défaut souhaitée.
Ne pas réimporter le realm de test sur un realm existant. Conserver base, comptes,
clients, secrets, issuer, URI exactes, flux d’authentification et version Keycloak.
Un retour arrière consiste à restaurer l’image et la sélection de thème précédentes ;
aucune migration de données n’est introduite.

Aucune visibilité sur la VM n’est revendiquée avant cette activation et sa recette.
Aucun tag, publication GHCR ou déploiement n’a été réalisé pour cette PR.

## HTTPS et thème de la VM : diagnostic en lecture seule, 1 novembre 2026

Identité SSH épinglée et identifiant d’installation vérifiés avant lecture.
Le DNS observé de `stockpilot-b2b-v021.mshome.net` résout vers `172.30.66.161`.
La composition utilise le proxy pour les ports 61914/61915 et l’image officielle
Keycloak 26.8.1, sans montage de thème. Une transaction PostgreSQL **READ ONLY**
montre `login_theme=NULL`, `display_name=StockPilot DEMO v0.2.1` sur `stockpilot-dev`.
Le titre visible vient donc du nom du realm, pas d’un thème privé identifié.

Les deux ports présentent exactement le même certificat SHA-256
`44bb7d952e4046641be0ac269c67f476302aa84f6869654421e24d3d44705641`.
Le certificat, signé par `StockPilot v021 Private Demo CA`, contient les SAN DNS
`stockpilot-b2b-v021.mshome.net` et `stockpilot-b2b-v021`. Il est valide du
1 novembre 2026 08:55:41 UTC au 1 novembre 2027 08:55:41 UTC ; la CA expire le
31 octobre 2028. Les deux handshakes TLS 1.3 réussissent avec vérification de
chaîne et de nom par un contexte SSL utilisant cette CA.

La CA est présente dans `CurrentUser/Root` Windows, empreinte SHA-1
`C150593BEE6A57869CF9CC119CC513955915780B`. Les requêtes Windows normales
`Invoke-WebRequest` vers `/b2b-app/` (61914) et la discovery OIDC (61915)
répondent **200**. L’issuer publié est bien HTTPS sur le nom DNS et le port 61915.
Les accès HTTP aux deux ports sont refusés **400**, sans redirection annoncée.

Limite avérée : aucun CRL Distribution Point n’est annoncé ; `curl` Windows/Schannel
avec ses vérifications par défaut échoue `CRYPT_E_NO_REVOCATION_CHECK`.
La disponibilité d’une révocation vérifiable n’est donc **pas qualifiée**.
La capture « Non sécurisé » antérieure n’a pas été reproduite dans son profil
navigateur exact : impossible d’en attribuer la cause unique à HTTP, au cache
ou à la confiance du profil. Rien ne prouve une différence de certificat entre
BFF et Keycloak. Aucune CA, configuration TLS, clé, donnée ou VM n’a été modifiée.
Une éventuelle évolution de révocation/certificat exigera une action opérateur
séparée autorisée ; aucun contournement TLS n’a été utilisé.

## Risques et portée du GO

Le point d’extension du thème dépend de Keycloak 26.8.1 : requalifier avant tout
changement de version. La campagne réelle est locale et n’est pas un contrôle
Keycloak automatiquement déclenché par la CI actuelle ; les Actions ordinaires
seront vérifiées sur le SHA final. Aucune revue indépendante n’a été réalisée.
Le GO éventuel porte sur la revue des changements testés, pas sur une mise en
production ou sur la visibilité actuelle de ce thème dans la VM.

## Recette après un futur déploiement

Avec `demo-b-user` puis `demo-b-admin`, choisir org-b, annuler depuis Keycloak,
vérifier le champ vide, choisir org-a puis vérifier le refus avec un compte org-b.
Recommencer sur org-b avec le bon compte, vérifier catalogue/permissions et absence
de contexte de l’autre compte. Tester mauvais mot de passe puis retour, nouvelle
connexion, déconnexion et « Changer de compte ». Vérifier le thème FR/EN, clavier,
le titre StockPilot AI et les deux URL HTTPS dans le navigateur Windows réel.
La revue de code ne vaut ni GO déploiement ni attestation de révocation TLS.
